# 部署与双机连接

## 用户需要做什么

两台电脑只需安装桌宠本身，不需要安装 Tailscale、远控客户端、浏览器插件或 VPN：

1. Mac 安装 `.dmg` 后固定显示“一二”，Windows 安装 `.exe` 后固定显示“布布”。
2. 首次打开时桌宠不会显示。先在 Mac 上点击“生成配对码”，再在 Windows 输入显示的 16 位配对码；双方验证成功后才会显示各自桌宠。
3. Mac 首次被查看时会触发 macOS“屏幕与系统音频录制”授权；授权后如系统要求，重新打开桌宠一次。
4. 以后右键宠物点“看看TA在干嘛”，会直接打开对方实时主屏幕。

应用首次启动会自动设置开机启动。操作系统或安全软件仍可能显示一次系统级确认，软件不会绕过系统权限。

## 绑定与安全边界

- 一次性配对码只用于 SPAKE2 首次握手，3 分钟内有效，不会保存或上传明文；服务端只看到不可逆的配对频道摘要。
- 双方分别签署同一份绑定记录，其中包含设备公钥和与绑定相关的机器特征。
- 设备私钥只保存在 macOS 钥匙串或 Windows 凭据安全存储中。
- EdgeOne 凭证函数会把服务锁定给第一份有效的双签名记录。GitHub 上下载的其他副本没有这两台机器的私钥，不能取得双机 UserSig，也不能加入屏幕房间。
- 每次查看请求都带有短时效、随机 nonce 和 Ed25519 签名，重放或伪造请求会被拒绝。

## 屏幕传输

- Rust/XCap 在被查看端捕获主显示器，缩放到最宽 1280px，不捕获麦克风、摄像头或系统声音。
- 画面在应用内存中转换为 10fps 自定义视频轨，交给内置 TRTC SDK 加密传输。
- 画面不写入磁盘，EdgeOne 和 Blob 不接触画面数据。
- 被查看时，本机宠物会持续显示“桌面正在分享”。

## 程序更新

- 客户端优先通过现有 EdgeOne 通道读取版本清单，GitHub Release 作为备用线路。
- EdgeOne 对大文件有单次响应上限，安装包和素材包使用 4 MiB 分段下载后在本地校验。
- 程序包必须通过 minisign 签名验证，素材包必须通过 Ed25519 清单签名和 SHA-256 校验；镜像不能替换更新内容。
- EdgeOne 三小时访问凭据由 GitHub Actions 每小时刷新两次，预留多轮调度延迟容错。

## 绝对双向解绑

1. 一方在设置中发起签名解绑请求。
2. 对方可以拒绝，或签名同意。
3. 请求方在验证批准签名后生成第三份确认签名。
4. EdgeOne 只在同时验证请求、批准、确认三份签名后标记白名单已撤销，随后双方本机才解除绑定。

没有恢复密钥、管理员覆盖或单机强制解绑入口。若一台电脑永久损坏，另一台无法单方解绑。双向解绑后再次绑定时，云端只接受原两台设备的同一对公钥。

## 开发者一次性云配置

用户不需要做这些。发布者需在腾讯云创建一个启用 IM 的 TRTC 应用，并将 `services/edgeone-realtime` 以海外地区部署到 EdgeOne Makers：

- 云函数环境变量：`TENCENT_SDK_APP_ID`、`TENCENT_SDK_SECRET`、`YIER_BUBU_OWNER_YIER_PUBLIC_KEY`。最后一项是 Mac 上“一二”的设备公钥，用来在两人第一次绑定之前就拒绝 GitHub 下载者抢占私有服务。
- GitHub Actions 仓库变量：`YIER_BUBU_REALTIME_ENDPOINTS=https://正式服务域名`。
- 使用全球可用区域且不含中国大陆，不需要 ICP 备案。

不得把 `TENCENT_SDK_SECRET` 写入前端、Rust 编译变量、GitHub 公开仓库或安装包。

## 构建

```bash
pnpm install
pnpm build
pnpm tauri build
```

Mac 与 Windows 安装包需在各自系统上构建。正式长期安装前应完成代码签名；未签名包仍可私人测试，但系统会显示开发者来源警告。
