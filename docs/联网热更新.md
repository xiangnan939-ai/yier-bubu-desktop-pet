# 联网热更新与发布

项目使用两条相互独立的更新通道：

- **程序更新**：Tauri 官方 Updater 下载 Mac/Windows 签名更新包，安装后重启。Windows 安装器会在更新时退出当前程序。
- **素材热更新**：下载签名的 `asset-manifest.json` 和版本化 ZIP。GIF 与 `rules.json` 可以在运行中切换，不需要重启。

没有配置发布地址的本地开发包会正常离线运行，只是在“设置 → 联网更新”中显示尚未配置。

## 一、准备 GitHub 发布仓库

建议使用单独的公开分发仓库。公开仓库只用于放安装包和素材附件。首次绑定口令、设备私钥和有效绑定记录均在运行时产生，不应也不会进入发布包；GitHub 私有仓库的 Release 下载需要登录鉴权，不能直接供当前无账号令牌的更新器使用。

把当前项目推送到仓库后，`.github/workflows/release.yml` 会在推送 `app-v*` 标签时同时构建：

- Apple Silicon Mac 更新包；
- 64 位 Windows 更新包；
- `latest.json`；
- 签名动作素材包和 `asset-manifest.json`。

## 二、生成程序更新签名密钥

在可信电脑上执行：

```bash
pnpm tauri signer generate -w tauri-update.key
```

把输出的内容分别保存到 GitHub 仓库设置：

| 类型 | 名称 | 内容 |
| --- | --- | --- |
| Actions Secret | `TAURI_SIGNING_PRIVATE_KEY` | 私钥全文 |
| Actions Secret | `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 生成私钥时使用的密码；无密码则留空 |
| Actions Variable | `TAURI_SIGNING_PUBLIC_KEY` | Tauri 输出的公钥 |

`tauri-update.key` 只能离线备份，不能提交到 Git。丢失私钥后，已经安装的旧版本无法信任用新私钥签出的更新。

## 三、生成素材清单签名密钥

素材通道使用独立的 Ed25519 密钥：

```bash
node scripts/generate-asset-update-key.mjs asset-update-private.pem
```

命令会同时打印并写出客户端使用的 Base64 公钥。也可以生成一次测试清单来验证整条发布链路：

```bash
python3 scripts/make-asset-pack.py \
  --version 0.2.2 \
  --base-url https://github.com/你的账号/你的仓库/releases/latest/download

YIER_BUBU_ASSET_PRIVATE_KEY="$(<asset-update-private.pem)" \
  node scripts/sign-asset-manifest.mjs \
  release-assets/asset-manifest.unsigned.json \
  release-assets/asset-manifest.json
```

随后配置：

| 类型 | 名称 | 内容 |
| --- | --- | --- |
| Actions Secret | `ASSET_UPDATE_PRIVATE_KEY` | `asset-update-private.pem` 全文 |
| Actions Variable | `ASSET_UPDATE_PUBLIC_KEY` | 脚本输出的“素材更新公钥” |

工作流会重新计算公钥并与 Variable 比较，不一致就停止发布。

## 四、发布新程序版本

发布前必须同步修改以下三个版本号：

- `package.json`
- `src-tauri/Cargo.toml`
- `src-tauri/tauri.conf.json`

例如把版本升级到 `0.2.3`，完成本地验证后：

```bash
git tag app-v0.2.3
git push origin app-v0.2.3
```

工作流完成后会公开 Release。两台电脑启动约 8 秒后检查一次，此后每 6 小时检查；也可以在设置中立即检查。程序更新只有在用户点击“更新并重启”后才安装，避免观看桌面或工作过程中被强制退出。

设置页会在程序包或动作素材包下载时显示已下载大小、总大小和百分比；服务器未提供文件总大小时显示循环进度，下载完成后切换为“正在验证并安装”。

## 五、只发布新素材

当前工作流会让素材版本跟随程序版本。若只改 GIF 或 `assets/action-rules.json`，可以手动生成一个更高的 SemVer 素材版本并把两个文件上传到最新 Release：

```bash
python3 scripts/make-asset-pack.py \
  --version 2026.8.1 \
  --min-app-version 0.2.2 \
  --base-url https://github.com/你的账号/你的仓库/releases/latest/download

YIER_BUBU_ASSET_PRIVATE_KEY="$(<asset-update-private.pem)" \
  node scripts/sign-asset-manifest.mjs \
  release-assets/asset-manifest.unsigned.json \
  release-assets/asset-manifest.json
```

上传 `character-assets-2026.8.1.zip` 与 `asset-manifest.json`。客户端只接受比本地素材版本更高或相同的 SemVer，不会降级。

## 六、可热更新的动作规则

`assets/action-rules.json` 目前支持：

- `sleepAfterSeconds`：多少秒无输入后进入睡眠；
- `ambientWeights`：`walk`、`look`、`sit`、`idle` 的相对权重；
- `drinkMinMinutes` / `drinkMaxMinutes`；
- `eatMinMinutes` / `eatMaxMinutes`；
- `workMinMinutes` / `workMaxMinutes`。

客户端还会对数值做范围限制。规则文件只能调整声明式参数，不能下发或执行远程代码。

## 七、安全与回滚

- 正式包只接受 HTTPS；开发模式只额外允许 `localhost`。
- 素材清单必须通过 Ed25519 签名；ZIP 必须匹配清单中的 SHA-256。
- ZIP 只允许两个人物目录下的 GIF 和根目录 `rules.json`，同时限制文件数量、下载大小和解压总量。
- 新素材先进入临时目录并完成校验，再整体切换；上一版保存在 `previous`。
- 如果切换过程中断电，下次启动会自动恢复上一版有效素材。
- 素材清单的 `minAppVersion` 可以阻止新版规则被旧程序错误加载。

如果之后改用 Cloudflare R2，只需要把工作流中的两个 `YIER_BUBU_*_URL/ENDPOINT` 改成 R2 的 HTTPS 地址，客户端协议和签名方式不变。
