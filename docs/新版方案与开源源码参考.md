# 一二布布私人桌宠：确认方案与开源源码参考

## 已确认的产品规则

- 软件仅由本人和情侣共同开发、共同使用，只允许一台 Mac 和一台 Windows 电脑配对。
- Mac 固定显示“一二”，Windows 固定显示“布布”，每台电脑只显示一只宠物。
- Mac 和 Windows 的右键菜单统一只显示：`看看TA在干嘛`、`设置`。
- 桌宠默认尺寸为 160px，可在设置中调整；设置中只显示绑定状态和双方解绑入口，不再暴露连接地址或长期密钥。
- 两台电脑完成首次配对和系统屏幕录制授权后，查看桌面不再要求对方逐次点击允许。
- 查看能力仅限已绑定的另一台设备；解绑必须得到两台设备的签名同意，不提供恢复密钥或单机强制解绑。
- 第一版只看桌面，不提供远程键盘、鼠标、剪贴板、文件传输、麦克风或摄像头控制。
- 画面不录制、不落盘、云端不保存。正在共享的电脑必须一直有可见状态，例如宠物动作、菜单勾选或托盘状态。

## 免重复授权的实现方式

这里有两层不同的“授权”：

1. **操作系统授权**：首次安装时，Mac 授予屏幕录制权限；Windows 完成捕获权限检查。这个权限由操作系统管理，程序不能绕过。只要应用身份和系统设置没有变化，后续通常不需要再次授权。
2. **情侣设备互信**：两台电脑首次输入相同口令，通过 SPAKE2 仅交换一次绑定会话密钥；随后固定双方设备公钥、Tailscale 节点身份和机器特征。口令不保存，后续每次连接都使用设备私钥签名，不再弹出逐次确认框。

连接流程：

```text
点击桌宠菜单
→ Tailscale 验证设备属于同一私有网络
→ 桌宠核对已绑定的 Tailscale 节点身份
→ 双方使用设备私钥完成随机挑战签名
→ 远端后台启动屏幕捕获
→ 由 Tailscale 建立加密连接（必要时使用加密中继）
→ 打开观看窗口
```

当前版本已经实现以下保护：

- 首次口令少于 8 个字符时拒绝绑定；SPAKE2 握手完成后立即丢弃口令。
- 设备公钥签名、Tailscale 节点身份或本机机器特征任一不符时，不启动屏幕捕获。
- 私钥保存在 macOS 钥匙串或 Windows 系统凭据安全存储，不进入前端存储、GitHub 或安装包。
- 解绑包含请求方签名和批准方签名；任何单边请求都不会改变绑定状态。
- 共享期间保持本机可见提示，但不要求逐次确认。
- 只实现看屏，不实现键鼠、文件、剪贴板、声音、摄像头和麦克风控制。
- 画面只在内存中编码和显示，不落盘、不上传数据库。

端口只监听 Tailscale IPv4 地址，不接受来自普通局域网网卡或公网网卡的连接。

## 推荐源码组合

### 1. 屏幕共享主参考：RASystem

- 仓库：<https://github.com/CasualOffice/RASystem>
- 许可：Apache-2.0，可在保留许可和声明的前提下参考、修改和复用。
- 匹配度：最高。它本身就是 Tauri 2 + Rust 的跨平台屏幕查看项目。
- 重点参考目录：
  - `app/src-tauri/`：Tauri 桌面壳和命令入口。
  - `crates/ras-media-macos/`：macOS ScreenCaptureKit + VideoToolbox。
  - `crates/ras-media-scap/`：跨平台屏幕捕获层，覆盖 Windows 捕获路径。
  - `crates/ras-media-openh264/`：Windows 的 H.264 软件编码回退。
  - `crates/ras-transport-iroh/`：加密 P2P 与中继回退。
  - `crates/ras-identity/`、`ras-grant/`、`ras-policy/`：设备身份、授权和能力限制。
  - `app/ui/viewer.js`：观看端 WebCodecs 解码与画面显示。
- 本项目的使用方式：只抽取“屏幕捕获 → 编码 → 加密传输 → 解码显示”的只读链路，不引入远程控制、剪贴板和文件能力。
- 风险：该项目仍处于 alpha，Windows 真机路径和安装发布需要在我们的两台实际电脑上重新验证，不能假定直接复制即可稳定工作。

### 2. 桌宠窗口与行为主参考：DesktopPet

- 仓库：<https://github.com/saagpatel/DesktopPEt>
- 许可：MIT。
- 技术：Tauri 2、React、TypeScript、Rust。
- 重点参考文件：
  - `src-tauri/tauri.conf.json`：透明、无边框宠物窗口。
  - `src/lib/petWindow.ts`：宠物窗口控制。
  - `src/pets/behaviorComposer.ts`：行为组合与状态逻辑。
  - `src/hooks/usePet.ts`、`usePetEvents.ts`：宠物状态和事件。
  - `src/components/pet/PetOverlay.tsx`：桌宠覆盖层。
  - `pet.html` 与 `panel.html`：宠物窗口和设置面板分离。
- 本项目的使用方式：参考窗口拆分、状态机、事件和测试结构，替换其企鹅/猫等素材和养成逻辑。

### 3. 透明窗口最小参考：Koi Pond

- 仓库：<https://github.com/crabnebula-dev/koi-pond>
- 许可：MIT。
- 重点参考：
  - `src-tauri/tauri.conf.json`：透明、无装饰窗口。
  - `src-tauri/src/lib.rs`：Tauri 桌面事件入口。
  - `.github/workflows/release.yml`：跨平台构建发布。
  - `src/updater.ts`：应用更新流程。
- 本项目的使用方式：当 DesktopPet 的结构过重时，用它校验最小透明窗口与发布配置。

### 4. 屏幕捕获原型参考：XCap

- 仓库：<https://github.com/nashaofu/xcap>
- 许可：Apache-2.0。
- 用途：快速枚举显示器、验证 Mac/Windows 截屏权限和选择主显示器。
- 限制：仓库将视频录制能力标为仍在开发，不能单独承担正式实时桌面共享链路。

## 本项目拟采用的代码结构

```text
src/
├── pet/                 2D 渲染、动作与移动状态机
├── behavior/            空闲、前台应用、电量、音乐等本机事件
├── menu/                两端不同的右键菜单文案
├── pairing/             仅两台设备的永久身份绑定
├── presence/            在线状态与轻量互动
└── viewer/              对方桌面的观看窗口

src-tauri/src/
├── platform/macos/      Mac 窗口、ScreenCaptureKit、权限检查
├── platform/windows/    Windows 窗口、Graphics Capture
├── capture/             捕获帧统一接口
├── codec/               H.264 编码和解码配置
├── transport/           P2P、重连和中继
├── trust/               已配对设备、公钥和会话令牌
├── autostart/           首次运行默认启用开机启动
└── updater/             签名自动更新

assets/characters/
├── 一二/
└── 布布/
```

## 实现顺序

1. 用 Koi Pond/DesktopPet 结构跑通透明桌宠窗口。
2. 读取“一二”和“布布”目录中的素材，完成基础动作状态机。
3. 用 RASystem 的媒体模块做两台电脑的只读画面传输验证。
4. 完成首次系统授权、设备公钥配对和后续自动接受连接。
5. 接入两端不同的右键菜单文案。
6. 最后增加电脑行为互动、开机启动和签名自动更新。
